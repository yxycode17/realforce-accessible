# REALFORCE 无障碍助手

面向视障用户的独立 Windows 键盘设置工具，使用标准窗口控件和键盘操作展示、编辑 REALFORCE 配置，方便使用读屏软件，减少对原版图形键盘、鼠标拖拽和 OCR 的依赖。

本工具不限定使用 NVDA，旨在兼容不同读屏软件。目前主要使用 NVDA 验证，其他读屏软件的兼容性仍需实际测试。

**版本：0.2.3 · 开发者：yxycode17**

本项目为独立辅助工具，非 Topre 官方软件。

## 当前适用型号

**0.2.2 开放 REALFORCE R3HB 系列，包括 HB11、HB13 及其他子型号。已实机验证的仍只有 R3HB11 / A0.17，通过 USB 连接。**

根据已分析的原版 4.1.1.0 通信库，布局由型号第 4 个字符决定：`R3HB` 开头的型号共用 `R30B.r3k`，后缀不参与布局选择。因此其他 HB 子型号按同一逻辑适配，并在设备状态中标明尚未实机验证。程序仍检查设备返回的功能标志，拒绝尚未支持的第三代 APC；开放型号不等于所有固件、连接方式均已验证。蓝牙直连下使用助手尚未验证。

### HA～HI 的布局与兼容性

以下对应关系来自原版型号解析和布局文件选择逻辑，表示系列对应布局，不代表每种后缀型号均实际销售。

| 系列 | 原版识别的布局 | 所需布局文件 | 当前助手 |
| --- | --- | --- | --- |
| R3HA | Windows 日文全尺寸 | `R30A.r3k` | 尚未适配 |
| R3HB | Windows 英文全尺寸 | `R30B.r3k` | 已开放；仅 HB11 实机验证 |
| R3HC | Windows 日文无数字区 | `R30C.r3k` | 尚未适配 |
| R3HD | Windows 英文无数字区 | `R30D.r3k` | 尚未适配 |
| R3HE | Mac 日文全尺寸 | `R30E.r3k` | 尚未适配 |
| R3HF | Mac 英文全尺寸 | `R30F.r3k` | 尚未适配 |
| R3HG | Mac 日文无数字区 | `R30G.r3k` | 尚未适配 |
| R3HH | Mac 英文无数字区 | `R30H.r3k` | 尚未适配 |
| R3HI | Windows 日文全尺寸 Space2 布局 | `R30I.r3k` | 尚未适配 |

这些系列在原版中共用 R3 通信实现，但实体键位置和名称依赖各自布局文件，不能套用 HB 的文件。目前打包内容仅有 `R30B.r3k`；其他系列需补充并核对相应布局和功能后再开放。Mac 指键盘布局，助手本身仍只在 Windows 运行。R3S、R4、GX1 等系列不在当前适配范围。

## 运行依赖

- Windows，安装 .NET Framework 4.8；不支持直接在 macOS、Linux 运行。
- 复制完整 `dist` 目录即可运行，无需安装原版或运行 CONNECT。
- `RealforceAccessible.exe`、`RFSWLib.dll` 和 `R30B.r3k` 必须放在同一目录；缺失时会报错，不回退到原安装目录。
- 使用已适配的 4.1.1.0 通信库。厂商文件仅保留在本地 `dist`，不提交到 Git；不打包 Windows 系统组件或 .NET Framework。
- 通信库按 SHA-256 校验。不同版本会停止连接，需要重新核对适配，不能直接删除校验绕过。
- 通过标准 Windows 无障碍接口供读屏软件访问，无需为助手安装专用读屏插件；不同读屏软件的实际操作体验仍需持续测试。

助手编译为 **AnyCPU**，在 64 位 Windows 上以 64 位进程运行。理论上可在具备兼容依赖的 32 位 Windows 运行，但没有做 32 位实机验证。

日常使用无需保留原版安装。若原版仍在运行，读取、保存或更新固件前请退出，避免同时访问设备。0.2.3 新增 USB 固件更新，尚未实机刷写验证；也可继续使用原版升级工具。

## 已实现功能

- 单台支持的键盘启动时自动读取；F5 手动更新当前配置。
- 当前 APC、ECO、A/B 方案、设备名称、固件及设备报告电量。
- 按实体键编辑 A 普通、A Fn、B 普通、B Fn 四层映射及两套逐键 APC。
- 已确认的 13 种 R3HB11 特殊功能使用中文名称并可重新选择：保存设置、APC 向前切换、蓝牙槽位 1–4、USB、开始/退出/删除配对、配对状态、电量查看和 ECO 设置；JSON 配置也支持恢复这些映射。
- 普通层设为 Fn 的键，其对应方案的 Fn 层不可编辑，保留上次读取值；改设为其他功能后恢复编辑。A/B 分别判断。导入会忽略锁定 Fn 层的变更并提示，保存前再次校验。
- 16 个自定义组合快捷键槽位：左右 Ctrl、Shift、Alt、Win 和主键。
- ECO LV4 自定义：指示灯开关、闲置动作和时间。
- 键盘名称编辑：最多 32 个英文、数字或半角符号。
- 按键统计列表，默认次数降序，支持确认后立即清零。
- 四个蓝牙配对槽位的状态、名称，以及最近连接槽位的只读显示。
- 改动清单、写入前备份、保存后读回检查、JSON 配置导入导出。
- 退出时对助手中未提交的编辑提供保存、放弃和取消选项。
- USB 固件更新：文件/型号/版本校验、再次确认、配置备份、阶段进度、失败弹框、升级后版本核对及自动刷新状态。

## 使用

运行 `dist\RealforceAccessible.exe`。仅有一台设备时会自动读取；多台时选择后按 F5。

| 操作 | 快捷键 |
| --- | --- |
| 设备状态及设备设置 | Ctrl+1 |
| 逐键设置：给实体键分配功能 | Ctrl+2 |
| 定义 16 个自定义组合快捷键槽位 | Ctrl+3 |
| 按键统计 | Ctrl+4 |
| 配对槽位信息 | Ctrl+5 |
| 切换分区 | Ctrl+Tab / Ctrl+Shift+Tab |
| 读取当前配置 | F5 |
| 关于、版本及开发者 | F1 |
| 列表中编辑所选按键或快捷键 | Enter |
| 移动焦点 | Tab / Shift+Tab |
| 关闭 | Alt+F4 |

例如：先在 Ctrl+3 将“快捷键 1”定义为 Ctrl+Shift+A，再在 Ctrl+2 把某个实体键的普通层或 Fn 层设为“自定义快捷键 1”。Fn 层是按住 Fn 时该实体键执行的功能。

## 当前配置与保存

F5 读取的是键盘当前配置，其中可以包含通过实体按键做出、尚未永久保存的调整。**读取基准不等于永久保存基准。**重新拔插后，未保存的键盘调整会还原。

“改动清单”只比较助手内的编辑与上次读取值。“助手中没有待保存的编辑”不表示键盘自身没有未保存的调整。当前没有助手编辑时，“保存到键盘”只提示无改动，不发送保存命令；实体按键调整请用 Fn+F12 保存。

用户实测：Fn+F11 和 APC 键首次用于显示或进入调整状态，短时间内再次按才切换。不能仅凭第一次按键后值不变，就判断读取失败。

统计清零与配置保存独立，确认后立即执行，不可撤销，不提交助手中的配置编辑。清零后可能立即计入新按键，因此读回不保证始终为零。

配置写入前的原始诊断备份位于 `%LOCALAPPDATA%\RealforceAccessible\Backups`，它与可导入的 JSON 配置文件不同，当前不支持自动恢复该原始备份。

### 保存和复用配置

1. 先读取键盘，再点击“导出配置”（Alt+X），保存为 JSON。包含助手当前编辑值，即使尚未保存到键盘也会导出。
2. 下次使用先读取键盘，再点击“导入配置”（Alt+I）。文件必须匹配当前完整型号、固件版本及布局/功能；即使同属 HB 系列，也不会跨型号导入。
3. 导入只替换助手内的配置编辑，不写入键盘。有待保存编辑时先询问是否替换；导入失败保留现有编辑。
4. 查看改动，点击“保存到键盘”。确认窗口可逐行阅读每项的当前值（上次读取）与目标值。写入前重新核对设备，发现外部变化将中止。

文件包含名称、APC 模式、两套逐键 APC、ECO 及 LV4 自定义、A/B 四层映射和组合快捷键。**不包含、也不通过导入修改当前 A/B 方案选择**；它仍由设备设置单独控制。统计、电量、配对信息及保留字节不导入。白名单外字段忽略并在导入结果列出；可修改字段的类型、整数范围、重复项和缺失项严格校验。未知特殊映射只能保留该键当前已有值，不能通过文件新分配。格式版本目前为 1，文件最大 1 MiB。

JSON 的 `model`、`firmware` 等元数据仅用于校验，不会写入键盘。导出的配置可能含自定义名称和键位，公开文件前请检查内容。

## 已验证和限制

- 已实机验证：配置、名称、统计和配对槽位读取；键盘名称修改、保存、重新拔插后的持久化（用户反馈）。
- 已做离线检查：键码编码、分块边界、比较基准隔离、统计排序、名称验证、外部配置变化检测、写入/读回失败处理、清零调用顺序及禁止不支持的灯光写入。
- 尚未逐项实机验证：APC/ECO/键位映射/组合快捷键写入后的实际效果、统计清零、退出时保存及保存失败路径、完整 NVDA 导航与刷新后的焦点表现。
- 本型号的原版 LED Color / Brightness 面板被隐藏，但仍可能出现在无障碍树中。助手不提供颜色和亮度自定义，也不将通用字段误报为实际灯光状态；ECO 自定义的指示灯开关继续保留。
- 电量为设备返回值。USB 无电池时可能报告 0%，不能据此判断电池健康状态。
- 配对信息只读，不支持清除配对、修改槽位名称；“最近连接槽位”不代表当前连接。
- 不支持固件降级、自动恢复或断点续传、恢复出厂设置、Mac 整套预设导入、原版配置文件导入或全部厂商特殊功能映射。部分已有特殊映射仅显示并保留。
- 不自动轮询。键盘实体按键调整后需按 F5；刷新会在存在助手编辑时询问是否放弃。

## 固件更新（0.2.3）

先保存或放弃编辑，仅通过 USB 连接一台受支持的键盘。点击“固件更新”（Alt+U）选择官方固件，校验通过后展示当前和目标版本。点击“开始更新”后仍需再次确认，默认“否”。CRC 检查完整性，不验证发布者身份。

确认后备份配置，重启设备，等待原 USB 路径重连，分块传输并核对返回序号。失败立即弹框并停止，不自动重发升级命令或重新刷写。升级后再次等待重连，核对型号、硬件标识和目标版本，成功后自动刷新主窗口状态。若只有状态刷新失败，会明确区分，不应因此重复刷写。

更新期间阻止正常关闭助手、请求防止自动睡眠，并向 Windows 注册关机/注销警告。强制关机、断电及系统崩溃无法可靠阻止。备份及日志位于 `%LOCALAPPDATA%\RealforceAccessible\FirmwareUpdates`；备份仅包含已读取配置，不是整个固件或配对密钥的备份，也不自动跨版本恢复。

**已通过模拟通信检查和 HB11 身份只读验证，尚未实际刷写固件。**详细流程及限制见 [固件更新说明](docs/固件更新说明.txt)。

## 从源码构建

首次构建请按以下顺序准备：

1. **先安装原版 REALFORCE CONNECT Software**，确保其中的 `RFSWLib.dll` 为本项目适配的 **4.1.1.0** 版本，并通过收集脚本的文件校验。
2. 在项目根目录运行 `tools\Collect-Dependencies.ps1`，自动校验并收集依赖，**无需手动创建目录或复制文件**。
3. 运行 `build.ps1`，将助手程序和使用说明生成到 `dist`。

安装原版后，可在项目根目录的 Windows PowerShell 中依次执行：

```powershell
.\tools\Collect-Dependencies.ps1
.\build.ps1
```

使用系统 .NET Framework 编译器，不需要 NuGet 还原。输出固定为 `dist`，只保留一份成品；请先退出正在运行的助手再构建。

### 各脚本的作用

| 脚本 | 具体功能 | 何时运行 |
| --- | --- | --- |
| `tools\Collect-Dependencies.ps1` | 校验原版通信库及布局文件的 SHA-256；自动创建 `dist`，将 `RFSWLib.dll` 复制为 `dist\RFSWLib.dll`，将 `Profile\R30B.r3k` 复制为 `dist\R30B.r3k`。不会复制原版 EXE。 | 首次构建，或 `dist` 中依赖文件丢失时。 |
| `build.ps1` | 引用 `dist` 中的通信库，编译助手并嵌入图标、键码名称表和版本信息；输出 `dist\RealforceAccessible.exe`，同时复制使用说明到 `dist`。 | 每次修改源码后重新构建。 |
| `tools\Convert-Icon.ps1` | 将 `assets\assistant.png` 转换为包含多个尺寸的 `assets\assistant.ico`。仓库已包含生成好的 ICO。 | 仅在更换图标源图时运行；普通构建无需运行。 |

收集脚本默认读取 `C:\Program Files (x86)\Topre\REALFORCE CONNECT Software`，可用 `-SourceDirectory` 指定其他原版目录。收集一次后，构建和运行都只使用 `dist` 内的厂商文件，不再需要原版安装。部署时复制整个目录，不能只复制 EXE。

例如，原版安装在其他位置时：

```powershell
.\tools\Collect-Dependencies.ps1 -SourceDirectory 'D:\Apps\REALFORCE CONNECT Software'
.\build.ps1
```

### 构建后检查

离线检查不访问键盘：

```powershell
Start-Process .\dist\RealforceAccessible.exe -ArgumentList '--self-test' -Wait
Get-Content .\dist\self-test.txt
```

`--probe` 为只读设备诊断，需退出原版程序，报告写到程序同目录的 `probe.txt`。报告可能含设备名称、槽位名称和键位配置，不应未经检查提交或公开。
